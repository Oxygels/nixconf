# CLAUDE.md

## What this is

Personal NixOS flake config for multiple hosts (`tower`, `laptop`, `wsl`), managed with
home-manager and disko. Three hosts share a common module base and opt in/out of GUI, disk
partitioning, and secrets via flags passed to a `mkHost` builder in `flake.nix`.

## Commands

- `nix flake check --no-build` — evaluate all `nixosConfigurations` and `packages` outputs without building. Use this after any change to `flake.nix` or modules.
- `scripts/switch.sh [host]` — regenerate hardware config and `nixos-rebuild switch --flake .#<host>` (defaults to current hostname). Requires sudo; only run when explicitly asked.
- `scripts/partition.sh /dev/xxx` — disko partition/format/mount. **Destroys the target disk.** Only for fresh installs, with explicit user confirmation.
- `scripts/install.sh <host>` — `nixos-install` onto a disk already mounted by `partition.sh`.
- `nix flake lock --update-input <name>` — update one flake input (e.g. `secret`, `nixpkgs`) without bumping the rest.

There is no test suite; `nix flake check` is the correctness gate.

## Architecture

- **`flake.nix`**: single `mkHost { hostname, username, gui ? true, disk ? true, secrets ? true, extraModules ? [] }` builder used for all three `nixosConfigurations`. Flags control which module sets get appended to the NixOS module list and the home-manager import list — this is the pattern to follow for any new optional subsystem (see how `gui` and `secrets` are wired, both in the `let mkHost = ...` block and the per-host calls at the bottom).
- **`hosts/<name>/`**: per-host NixOS config (`default.nix`), hardware config (checked into git, regenerated by `scripts/switch.sh`/`install.sh`), and `home.nix` for host-specific home-manager settings (monitor layout, host-specific packages). `wsl` runs with `gui = false; disk = false; secrets = false`.
- **`modules/nixos/core`** and **`modules/home/core`**: always-on modules for every host (networking, security, shell, git, lf, fish, nvim via lazyvim, btop, claude-code, ssh).
- **`modules/nixos/gui`** and **`modules/home/gui`**: Hyprland desktop stack (quickshell bar in QML, hyprlock, easyeffects, brave, udev rules), only pulled in when `gui = true`.
- **Quickshell QML (`modules/home/gui/quickshell/qml/`) does not hot-reload.** `~/.config/quickshell/default` is a home-manager-managed symlink into the Nix store (`xdg.configFile."quickshell/default".source = ./qml`), so editing files in the repo has zero effect on the running shell until `scripts/switch.sh` is actually run — there is no live-reload fallback to lean on. After switching, the running `quickshell` process also needs restarting (`quickshell kill` then relaunch, or relog) to pick up the new store path, since it doesn't watch files by default either. When debugging a QML change that "isn't working," verify the deployed file under `~/.config/quickshell/default/...` actually contains the edit before assuming the QML logic is wrong.
- **`nixpkgs-unstable`** is a separate flake input used only when a package needs a fix/version not yet in the pinned `nixpkgs-26.05`. `modules/home/gui/unstable.nix` is the single point of contact with it (imports `nixpkgs-unstable` itself rather than relying on `pkgs`, so the rest of the config stays on the pinned channel) — each package pulled from there documents why it can't come from pinned nixpkgs. Follow that pattern (one file, comment the reason) rather than switching a whole module to unstable.
- **Secrets are not in this repo.** They live in a separate private repo (`github:Oxygels/nixconf-s`) pulled in as the `secret` flake input (`flake = false`) and referenced as `"${secret}/home"` in the home-manager import list, gated by the `secrets` flag. That private repo contains the sops-nix home-manager module (`home/`), the encrypted secret files (`secrets/*.yaml`), and its own `.sops.yaml`. To edit a secret, clone that repo separately and run `sops secrets/<file>.yaml` there; `sops.age.keyFile` is read from `~/.config/sops/age/keys.txt` on the target machine. Bumping secrets here requires `nix flake lock --update-input secret`.
- **`disko`** module (`modules/nixos/core/disk-config.nix`) is imported with a placeholder `device`; the real device only comes from `--argstr device` via `scripts/partition.sh`, never from the flake itself.
- home-manager is wired with `useGlobalPkgs`/`useUserPackages` and `backupFileExtension = "bak"`; all flake inputs are passed through as `extraSpecialArgs` to home-manager modules and as `specialArgs` (plus `hostname`/`username`) to NixOS modules.
